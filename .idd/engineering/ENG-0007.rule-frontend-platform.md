# ENG-0007.rule-frontend-platform

## Rule

Поддерживаемый исходный код интерфейса FigVam реализуется на TypeScript со строгими проверками, включая noImplicitAny, strictNullChecks и noUncheckedIndexedAccess; ошибки типов не обходятся массовыми any, отключением проверок или необоснованными приведениями. Декларативный интерфейс приложения строится на React, собирается Vite, стандартные контролы переиспользуют Base UI, стандартные иконки — Lucide React. Зависимости фиксируются lock-файлом и добавляются по обоснованной необходимости.

HTTP-контракты выводятся из серверной OpenAPI-спецификации, а недостаточно полные контракты дополняются типизированными адаптерами без изменения семантики сервера. Транспорт, команды, ревизии, авторизация и совместное редактирование имеют явных владельцев и сохраняют действующие гарантии. Графический движок не зависит от React; React не управляет DOM-поддеревом движка. UI Kit приложения и отображение пользовательских документов не смешиваются; компоненты не дублируют доменные правила backend.

Рукописные исполняемые frontend-модули не размещаются в wwwroot: там находятся статическая разметка и стили, а JavaScript генерируется сборкой. Обычные панели не создают собственные React roots или параллельные legacy-реализации; прямые порталы для обычных панелей и переходные адаптеры запрещены; панели размещаются декларативно и получают типизированные данные и действия. Переиспользуемые контролы документируются в UI-KIT.md. Специализированные контролы и canvas допускают собственную реализацию с явной границей владения DOM и освобождением ресурсов.

Новые обычные формы и панели получают состояние и действия через типизированные модели или React props. DOM-атрибуты hidden/disabled/inert и текст являются результатом отображения, а не источником состояния; запрещено передавать состояние между контроллерами через DOM ID, селекторы и синтетические события. Допускаются DOM-операции для фокуса, измерений, нативного выбора файла, браузерных API и графического движка. Для существующих legacy-контролов миграция выполняется по feature-модулям без добавления новых зависимостей от DOM. Все обычные команды изменения документа создаются через типизированные подготовленные операции api/document-commands.ts. Их имя связывается с типом запроса и ответа из OpenAPI. Подготовленная операция сохраняет сериализованный payload и commandId, не выполняет скрытых повторов, защищена от параллельной отправки и проверяет ответ сервера. Повтор неопределённой команды сохраняет исходные commandId и payload; подтверждённая команда после ошибки синхронизации повторяет только чтение. Конфликт не меняет expectedRevision уже отправленной команды: новое намерение создаётся после получения актуального состояния. Сессия имеет явно созданного владельца с собственным сроком жизни, отменой и эпохами. Смена сессии инвалидирует даже запросы с тем же токеном.

## Applicability

Conditional

## Applies when

Создание, изменение или сопровождение frontend-приложения FigVam, его компонентов, клиентских контрактов и графического движка.

## Verification

Строгая проверка TypeScript, воспроизводимые сборка и генерация API-типов, модульные тесты критичной логики и существующие регрессионные сценарии. Сгенерированные frontend-ресурсы публикуются с ASP.NET без отдельного Node.js сервера.

Автоматические frontend-тесты контролируют отсутствие рукописного исполняемого JavaScript в исходниках и wwwroot, единственную точку создания React root, отсутствие прямых адаптеров порталов и legacy-разметки в index.html и независимость Canvas от React, UI Kit и контроллеров приложения. AST-проверки запрещают прямые URL команд вне инфраструктуры команд, явный any, отключение проверки типов и runtime-циклы импортов; feature-модули не импортируют Composition Root. Дополнительная проверка запрещает прямой ID-доступ к уже мигрированным полям оболочки и регистрацию обычных UI-обработчиков в editor.ts. Синхронное монтирование допускается на границе запуска старых контроллеров; синхронные обновления — только там, где нужен немедленный фокус или измерение DOM.

### Session and mutation ownership

Authentication mode and CSRF belong to an injected instance, not module globals. Session lifetime and document navigation cancellation are distinct from the foreground lane. Use prepared operations for asset uploads as well as JSON commands. Keep known transport rejection separate from stale UI application. React-owned classes and markup derive from state; only bounded popup positioning and canvas/browser primitives may mutate geometry directly. Compare browser performance against main and record post-GC heap checkpoints after at least 20 navigation cycles.
