Выполни этап инженерной стабилизации проекта перед дальнейшей реализацией приложения.

Используй IDD Factory, режим `intent-preserving`. Текущие Product Intent и Engineering Rules являются обязательными. Не изменяй их, не добавляй новых требований или неподтверждённых возможностей Portable UI Profile.

Если существует активная Factory-задача, используй штатную процедуру безопасной замены после подтверждения остановки предыдущих Worker. Не удаляй вручную Factory state и не теряй промежуточные изменения.

**Задачи:**

1. Настрой GitHub Actions CI: сборка решения, серверные тесты и Playwright. Проверь полный прогон и исправь реальные ошибки. Если требуется `.idd/verification.yaml`, используй штатный `idd-verification-configure`, соблюдая его правила подтверждения.
2. Проведи декомпозицию `editor.js` по функциональным областям. Выдели независимые модули, общий API-клиент, состояние сессии и управление асинхронными запросами. Сохрани существующее поведение.
3. Устрани дублирование источников возможностей Portable UI Profile между сервером и клиентом. Сервер должен оставаться авторитетным источником. Не расширяй пока производственный профиль.
4. Проверь наиболее крупные backend-модули на нарушение ответственности, дублирование и нежелательные зависимости. Рефакторинг выполняй только там, где есть подтверждённая инженерная проблема, а не ради уменьшения количества строк.
5. Актуализируй устаревшие технические описания. Не переписывай нормативный Intent на основе текущей реализации.

**Правила выполнения:**

- Разделяй работу на небольшие проверяемые этапы.
- Не допускай новых функциональных возможностей или изменений публичных контрактов.
- Сохраняй совместимость форматов документов, команды, ревизии, авторизацию и существующие сценарии.
- После каждого этапа запускай соответствующие проверки.
- В конце выполни полный набор проверок и focused `idd-intent-drift-audit`.
- Не занимайся косметическим рефакторингом без доказанной пользы.

Результат: стабилизированная инженерная основа, успешно работающий CI, подтверждённое отсутствие функциональных регрессий.

После завершения остановись, кратко перечисли внесённые изменения, оставшиеся риски и готовность проекта продолжать реализацию по IDD.
