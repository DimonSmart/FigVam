# IDD-0014.spike-portable-profile

## Вопрос

Какие конструкции и свойства могут получить одинаковую проверенную семантику во всех четырёх целях? Исследование необязательно для текущей версии и не блокирует включение возможностей в браузерный профиль.

## Исследование

Сравнить HTML/CSS, WPF, Avalonia и Uno для автокомпоновки, переноса и измерения текста, baseline, Hug/Fill, clipping, простого ввода и прокрутки. Исследовать фиксированный Grid, Wrap, fallback шрифтов и допустимые геометрические отклонения.

Кандидаты включают Frame, Rectangle, Ellipse, Line, текст и изображение; свободное размещение, Stack и фиксированный Grid; Fixed/Content/Fill, min/max, padding, gap и выравнивание Start/Center/End/Stretch; сплошную заливку, обводку, радиус и прозрачность. Для текста рассматриваются шрифт с fallback, размер, вес, цвет, line height, выравнивание и перенос; для изображений — contain, cover, stretch и поддерживаемый crop. Кандидаты семантических ролей: Label, Button, TextInput, CheckBox, Image, List, Panel и Tab; также рассматриваются повторение с пустым состоянием, именованные варианты и токены тем. Сложные фильтры и маски находятся вне кандидатного профиля.

Для будущего объявления поддержки платформы зафиксировать отображение и автоматические проверки на этой платформе. Точные типы контролов, безопасное подмножество SVG, RTL и ограничения размеров документа требуют отдельного подтверждения.

## Эксперимент: пустой Frame фиксированного размера (2026-11-16)

Исследовательские проверки находятся в [research/FramePortability](../../research/FramePortability/run.ps1).
Повторение из корня репозитория: `pwsh -NoProfile -File research/FramePortability/run.ps1`.
Нужны Windows, PowerShell 7, .NET SDK из `global.json`, NuGet, установленный Edge
и доступный desktop для Uno/Win32. Скрипт восстанавливает отдельные исследовательские
проекты в locked mode, запускает все четыре проверки и возвращает ошибку при
отказе любой из них; зависший процесс проверки завершается через 180 секунд.
Отсутствующая платформа не считается успешной проверкой.

Общий [набор входных размеров](../../research/FramePortability/cases.json):
320×180, 123.5×67.25 и 1×1 uiUnit, без детей, текста, заливки и обводки.
Исследовано отображение структурного неинтерактивного контейнера: HTML `div`
с CSS `width`/`height`, WPF `Grid`, Avalonia `Grid`, Uno `Grid` с XAML
`Width`/`Height`. Название узла-кандидата Frame не означает использование
навигационного контрола `Frame`. Эти проверки не добавляют разрешённые
возможности в производственный профиль.

Подтверждённый запуск: Windows 10.0.26200, SDK 10.0.204, WPF/.NET 10;
Edge/Chromium 157.0.4341.60 через Playwright 1.64.1; Avalonia 12.1.6 с
headless platform и реальным Skia renderer; Uno.Sdk 7.0.22 / Uno.WinUI 7.0.65,
Skia Desktop/Win32. Зависимости зафиксированы в `packages.lock.json` проектов.

| Цель и условия | Подтверждённый результат |
| --- | --- |
| HTML/CSS, viewport 640×480, light, DPR 1/1.5/2 | Все три размера совпали с `getBoundingClientRect` в CSS px; пустой `div`, `display:block`, без focus/tab stop и явной ARIA-роли. В Chromium AX tree нет интерактивной роли. |
| WPF, Measure/Arrange в DIP, bitmap 96 DPI | Все три размера совпали с ActualWidth/ActualHeight; пустой нефокусируемый Panel; automation peer не создаётся. |
| Avalonia, headless Skia, bitmap 96 DPI, UseLayoutRounding=false | Все три размера совпали с Bounds в логических единицах; пустой нефокусируемый Panel; automation peer имеет роль None. |
| Uno, Skia/Win32, масштаб Windows 1.25, UseLayoutRounding=false у контейнера и корня | Все три размера совпали с ActualWidth/ActualHeight с допуском 0.0001 логической единицы; пустой Panel; automation peer не создаётся. RenderTargetBitmap дал 400×225, 154×84, 1×1 физических пикселей соответственно. |

На каждой цели получен bitmap пустого контейнера и проверена нулевая alpha
всех пикселей. Отдельная калибровка той же render pipeline красным фоном
подтверждает, что bitmap действительно содержит результат рисования, а не
пустой результат неработающего renderer. Красный фон — только средство
измерения; заливка этим экспериментом в профиль не допускается.

Выявлено ограничение дробной геометрии: при исходном стандартном округлении
Uno на масштабе 1.25 размер 123.5×67.25 превратился в
123.19999694824219×67.19999694824219; Avalonia со стандартным округлением
также не прошла проверку этого дробного размера. Отключение layout rounding
в исследуемом отображении устранило расхождение. Физические размеры bitmap
округляются отдельно и не определяют размеры документа в uiUnit.

Границы вывода: подтверждены только указанные входы и реализации целей.
Общая отдельная accessibility-роль Panel не подтверждена: отсутствующий
peer WPF/Uno и None Avalonia не равны объявленной роли панели. Проверка
Chromium AX tree ограничена отсутствием интерактивных ролей. Внешние screen
reader/UIA-проверки, Preview FigVam, нулевые/предельные размеры, другие DPI
настольных целей, браузеры, темы и другие Uno heads не проверены. Шрифты,
дети, clipping, события и дополнительные свойства вне этого опыта.
По этим результатам поддержка Portable UI Profile ещё не объявляется.

В текущем домене `INodeProfile` предоставляет только IsKnownKind,
CanContainChildren и GetProperty; NodePropertyValidator проверяет отдельные
значения, DocumentStructureValidator — структуру через переданный профиль.
Производственного реестра с отображениями целей и семантической ролью,
а также Preview пока нет. Исследовательские проекты не регистрируются как
производственный профиль и не создают альтернативные списки разрешённых
возможностей. Этот результат уточняет границы исследования и не ограничивает браузерный профиль.
