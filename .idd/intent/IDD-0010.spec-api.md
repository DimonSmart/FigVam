# IDD-0010.spec-api

V1 предоставляет независимый от браузера и UI-сессии программный API чтения и изменения дизайна с теми же правами, проверками и командами, что и UI. Произвольная запись по JSON-пути не допускается. API поддерживает компактные запросы документов, страниц, экранов, узлов и детей с поиском, фильтрами по экрану, виду, semanticKey и префиксу имени, выбранными полями, ограничением глубины и пагинацией; компонентов и использований, токенов, вариантов, сценариев, датасетов и их схем, текстового каталога, диагностики и разниц ревизий или вариантов. Диагностика по области возвращает коды и пути элементов; разницы дают компактные списки изменённых свойств. Запрос принимает documentId, а где применимо — revision, screenId, variantId, datasetId, themeId и ограничение объёма. Большие ответы имеют summary или пагинацию. Live data и секреты не возвращаются по умолчанию.

Командный API принимает типизированные операции и commandId, возвращает статус, revision и затронутые объекты либо структурированный код и объяснение отказа. actorId определяется сервером. Визуальный запрос формирует изображение указанного экрана, варианта, темы и фикстуры при заданных размерах и машинно читаемые ID и bounds; временная подмена текстов не меняет документ. Сравниваемые локализационные снимки используют одинаковый либо явно зафиксированный набор текстов.

Публичные DTO и коды ошибок документируются через OpenAPI; JSON Schemas формата и DTO публикуются и проверяются контрактными тестами. Имена действий и ошибок не зависят от клиента. Несовместимое изменение требует новой версии API и периода миграции. Независимые запросы и команды дают доступ к дереву экрана, типизированным свойствам, вычисленной геометрии и диагностике, созданию и изменению компонентов и управлению вложенностью. Будущий MCP является адаптером тех же запросов и команд, а не отдельной моделью правил; он не обязателен в V1.
