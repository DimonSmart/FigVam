# IDD-0008.spec-commands-collaboration

Все изменения документа проходят типизированные доменные команды через общий обработчик для UI и программных клиентов. Для каждого документа существует один авторитетный последовательный поток; разные документы могут обрабатываться параллельно. На команду проверяются права, commandId, цели, типы, профиль и применимые предусловия. Принятие атомарно, надёжно фиксирует результат и новую строго возрастающую revision до ACK, после чего изменение распространяется подписчикам. Отказ не меняет документ или revision; пакет независимых команд не является атомарным без явного объявления. Повтор commandId возвращает первоначальный результат без повторного применения.

Команды покрывают создание страниц, экранов, узлов, компонентов и экземпляров; удаление, свойства, перемещение, смену родителя и порядка; токены, варианты и overrides; переходы, привязки и сохранённые версии. Создание узла вместе с начальными допустимыми свойствами выполняется атомарно. Одна операция изменения связанных свойств, включая перемещение и изменение размера, также атомарна: отказ не оставляет частичного результата. Малые типизированные операции не требуют передачи полного дерева. Актор определяется сервером по аутентификации.

Если узел удалён до поступления операции, вернуть NODE_NOT_FOUND без его восстановления. Последняя применённая допустимая запись свойства определяет значение. При несоответствии ожидаемого родителя операция, зависящая от прежнего контекста компоновки, отклоняется с INVALID_LAYOUT_CONTEXT. expectedRevision применяется там, где семантика зависит от предыдущего состояния; адресные предусловия могут проверять родителя, значение или ревизию узла. Сервер назначает технические ID либо принимает клиентские UUID с проверкой уникальности; одинаковые человекочитаемые имена допускаются, если это разрешает семантическое пространство имён.

Подтверждённое событие содержит documentId, revision, commandId, actorId, тип и минимальную полезную нагрузку. Клиент отслеживает следующую ожидаемую ревизию и при пропуске или reconnect получает события начиная с lastSeenRevision + 1 либо полный актуальный снимок при недоступности истории. Временное отключение не меняет прав. Presence показывает имя/цвет, курсор, выбранные ID и экран; оно эфемерно, имеет TTL, может теряться или агрегироваться и не создаёт ревизий. Viewport участников не обязан совпадать. Экспорт и параллельное чтение используют согласованный снимок конкретной ревизии.

Проверять двух клиентов, конкурирующее удаление, повтор после потери ACK, пропуск событий и сходимость как минимум пяти редакторов.

## Атомарное пакетное исполнение

Разрешённые редактирующие команды MCP могут выполняться последовательно над временным состоянием внутри одной транзакции. Проверяются все предусловия обычных команд; одна внешняя ревизия и один commandId. Публикуется только итоговая ревизия, без промежуточных событий. При отказе пакет полностью откатывается.
