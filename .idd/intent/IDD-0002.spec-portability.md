# IDD-0002.spec-portability

FigVam использует платформенно-независимую декларативную модель визуального дизайна. При проектировании учитывается возможность последующего преобразования в HTML/CSS, WPF, Avalonia и другие UI-фреймворки. Межплатформенная переносимость желательна, но не является критерием готовности текущей версии: проверяемое представление — браузерный Preview. Генерация платформенных форматов и подтверждение межплатформенной эквивалентности не обязательны; неподтверждённая совместимость сама по себе не ограничивает возможности профиля.

## Единственный Portable UI Profile

В текущей стадии разработки существует ровно один профиль `figvam.portable-ui/4`. Все новые документы используют его сразу. Старые версии профиля, реестры их возможностей, команды обновления, автоматические и ручные миграции отсутствуют. Сохранённых пользовательских документов нет, поэтому совместимость форматов профиля с предыдущими реализациями не требуется. Версия формата `document.json` и ревизии/сохранённые версии отдельных документов — самостоятельные механизмы, не являющиеся версиями Portable UI Profile.

Профиль определяет допустимые типы узлов, родительство, свойства, типы и ограничения значений, умолчания, семантические роли, события и действия Preview. Палитра, инспектор, серверная валидация и Preview используют единый реестр; неподдерживаемые значения отвергаются с диагностикой объекта, свойства и причины. Цвет допускает прямое значение или ссылку на цветовой токен. Произвольные платформенные атрибуты и строки не обходят типизированную проверку. Модель не зависит от HTML, CSS, DOM и браузерных API. Масштаб редактора не изменяет документ. Исследования переносимости остаются необязательным направлением развития (IDD-0014).

TextInput получает типизированный `inputType` со значениями `Text` (по умолчанию) и `Password`, а однострочный TextInput поддерживает декларативное событие `Submit`. Ввод пароля не сохраняет секреты и не выполняет авторизацию.

## Атомарные дизайн-токены

Текущий профиль поддерживает категоризированные атомарные токены непосредственно в свойствах узлов. Dimension хранится в логических единицах профиля, Number безразмерен; конвертация в CSS px является задачей браузерного рендерера, а не доменной модели. При разрешении сервер проверяет ID, тип и категорию, тему Light/Dark, всю цепь алиасов, типизированный результат и ограничения конкретного свойства. Клиент должен повторять эту семантику без дополнительных несовместимых интерпретаций. Не создаются специальные правила для HTML, WPF или конкретных контролов и не вводятся формулы/каскад.
